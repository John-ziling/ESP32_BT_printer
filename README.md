## 项目简介

用通用 MCU（ESP32）复现一台便携热敏打印机的全部固件：打印头驱动、步进电机走纸、
缺纸/温度/电量三类检测、经典蓝牙 SPP 通信，以及一整套逆向自官方 App 的私有协议。

**能做什么**

- [x] 经典蓝牙 SPP，设备名 `MaoPaperang_Q`，直连喵喵机 App 完成握手并打印
- [x] 打印头驱动：SPI 送数、LAT 锁存、6 段 STB 分段加热、VH 升压使能
- [x] 步进电机八拍半步走纸，32 步/mm
- [x] 缺纸检测（2 秒一次非阻塞告警，打印前与每行都检查）
- [x] 电池电压采样 + 101 点查表电量，低电分级保护
- [x] 打印头 NTC 测温 + 线性温度补偿 + 过温中止
- [x] 状态灯（打印常亮 / 缺纸过温快闪 / 低电慢闪）
- [x] 空闲自动待机（关蓝牙、关打印头电源，按键唤醒）
- [x] 内置程序生成自检图案、整页缓冲（上限 64KB）、链路排空防串帧

**不适合做什么**：打印速度约 3.7 mm/s，是"内容打印机"（便签/错题/清单/短凭证），
不是收银或外卖打印机（原因见[已知限制](#已知限制)）。

## 硬件要求

本项目基于自制 PCB（原理图与嘉立创 EDA 工程见 `文档/资料/`），核心器件：

| 器件 | 用途 |
|---|---|
| ESP32-WROOM-32E | 主控，4MB Flash，无 PSRAM |
| JX-2R-01 机芯 | ROHM 384 点热敏头 + 两相四线步进电机（同一根 FPC） |
| TC1508S | 双 H 桥电机驱动（电压驱动，非恒流） |
| AP2005 | 升压到 VH ≈ 8.4V 供打印头（输出电容 47µF） |
| TP4056 | 单节 18650 充电 |
| CES806G + AO3401A | 软开关（长按开/关机） |
| LM393 | 缺纸光电信号整形（开漏输出需上拉） |

**引脚分配**（`include/config.h`）

| 信号 | GPIO | 说明 |
|---|---|---|
| CLK | 15 | SPI 时钟，1MHz / MODE0 / MSB first |
| DI | 13 | SPI MOSI，打印点阵数据 |
| LAY (LAT) | 12 | 锁存，**idle 低 / 脉冲高**；GPIO12 是 strapping 脚，idle 低正好安全 |
| STB1~6 | 14/27/26/25/33/32 | 6 段加热使能，高有效 |
| VH_EN | 17 | 打印头升压电源使能，不打印必须关 |
| PHINT | 35 | 缺纸检测，HIGH = 缺纸（纯输入脚，外部上拉） |
| TEMP | 36 | 打印头 NTC（纯输入脚） |
| POWER_ADC | 34 | 电池分压（纯输入脚） |
| MOTOR AP/AM | 22 / 23 | TC1508S IN2 / IN1 → A 相 |
| MOTOR BP/BM | 19 / 21 | TC1508S IN4 / IN3 → B 相 |
| BTN | 5 | 按键，内部上拉，按下为 LOW（⚠ strapping 脚，别按住上电） |
| LED | 18 | 状态灯，低电平点亮 |

## 快速开始

**工具链**：VS Code + PlatformIO（平台 `espressif32@8.0.0`，Arduino 框架）。

```bash
pip install platformio            # 或安装 VS Code PlatformIO 插件
python 工具/patch_bt_rx_queue.py  # 必做：蓝牙接收队列 512 → 20480，否则大图丢包
pio run                           # 编译
pio run -t upload                 # 烧录
pio device monitor                # 串口日志，115200
```

烧录后串口应依次出现：

```
协议自检：OK
蓝牙已启动，设备名称：MaoPaperang_Q
```

冒烟测试（用串口蓝牙助手连上后发 HEX）：

```
发：02 04 00 00 00 21 95 76 35 03        （GET_VERSION）
收：02 04 00 01 00 00 46 89 5E 9E 03      （ACK）
```

> 框架升级后 `patch_bt_rx_queue.py` 需要重跑——它改的是 PlatformIO 包目录里的文件，不在本仓库内。

## 连接上位机

一台打印机同一时刻只能连一个上位机：

| 上位机 | 连接方式 | 说明 |
|---|---|---|
| Android | 经典蓝牙 SPP | 系统蓝牙配对 `MaoPaperang_Q`，再装喵喵机 App |
| Windows | SPP → COM 口 | 配对后在"设备和打印机 → 属性 → 服务"勾选串行端口，**用"传出"那个 COM** |
| iPhone | ❌ 用不了 | iOS 只开放 BLE，需换传输层（见[路线图](#路线图) M4） |

## 通信协议

### 帧格式

```
┌──────┬──────┬──────┬───────┬───────┬─────────┬────────────┬──────┐
│ 0x02 │ type │ idx  │ lenL  │ lenH  │ payload │ CRC32 (LE) │ 0x03 │
└──────┴──────┴──────┴───────┴───────┴─────────┴────────────┴──────┘
  1B     1B     1B     1B      1B       len B        4B         1B
```

- 总长 = len + 10；载荷不做转义，定界完全靠 len（不能靠找 0x03）
- 命令码偶数为请求、奇数为对应应答（如 GET_VERSION=4 / SENT_VERSION=5）；ACK 回显请求码
- 查询类回 `SENT_*` 数据帧，其余回 11 字节 ACK，**未知指令也一律回 ACK**（否则握手会卡死）

### CRC32（真机实测，与教程写法不同）

- **只覆盖 payload**，不覆盖帧头；
- App 混用两套初值：SET_CRC_KEY 那一帧用 **crcKey `0x35769521` 作初值**（空载荷帧的 CRC 恒等于 key 本身），其余帧用标准 zlib 初值 `0xFFFFFFFF`；
- 固件按多规则容错校验，命中的规则编号记在 `Frame::crc_rule`，串口只在规则变化时提示；
- 校验失败的帧**不回任何应答**，让上位机超时重发。

### 握手（10 步，连上后 App 依次发）

```
SET_CRC_KEY → GET_SN → 66（型号）→ 127（固件版本）→ SET_HEAT_DENSITY
→ GET_DEV_NAME → GET_BAT_STATUS → GET_POWER_DOWN_TIME → GET_VERSION → SET_PAPER_TYPE
```

### 打印下发

```
SET_HEAT_DENSITY ×2   设浓度（App 实测发 95）
FEED_LINE（第 1 次）  开始一页：清空页缓冲
PRINT_DATA ×N         位图数据，每包 ≤1920 字节 = 40 行，每包回 ACK
FEED_LINE（第 2 次）  触发打印：先回 ACK 再开始打（避免 App 6 秒超时重发导致重打）
```

## 打印时序与性能

一行（0.125mm）的耗时构成：

| 阶段 | 耗时 | 占比 |
|---|---|---|
| 电机 4 半步 @2000µs | 8.0 ms | 24% |
| `delay(2)`（喂看门狗） | 2.0 ms | 6% |
| SPI 48 字节 @1MHz + LAT | 1.4 ms | 4% |
| **6 段加热（每段约 3.4ms）+ 段间冷却 300µs** | **22.2 ms** | **66%** |
| **合计** | **≈33.6 ms / 行** | 等效 **3.7 mm/s** |

速度卡在硬件，不在软件：单段加热需要约 73mJ 能量，而 47µF 升压电容只存 1.66mJ、
升压只能补约 22mJ——VH 必然下跌，段间冷却就是留给电容回充的时间。
想快只能加大 VH 电容、降 VH 或换更大功率升压，都是硬件改动。

## 保护机制

| 项目 | 阈值 | 动作 |
|---|---|---|
| 缺纸 | PHINT 高电平 | 绝不加热；打印前与每行检查 |
| 低电（告警） | < 3.60 V | LED 慢闪 |
| 低电（开始） | < 3.55 V | 拒绝开始新打印 |
| 低电（打印中） | < 3.40 V | 每 32 行复核一次，低于立即中止（防掉压复位） |
| 打印头温度 | ≥ 50 ℃ | 线性缩短加热时间（80℃ 时约为 70%） |
| 打印头温度 | ≥ 80 ℃ | 每 8 行检查一次，超过立即中止 |
| 空闲 | 默认 60 分钟（App 可设） | 进入待机：关蓝牙、关打印头电源、灭灯 |

页缓冲按 8KB 翻倍扩容、上限 64KB（约 1365 行 / 170mm）；溢出或内存不足时**整页作废**，
触发打印时明确拒绝——不"假装成功"。打印结束/中止后排空蓝牙链路并复位解析器，
防止积压的残留字节被当成下一单的新指令。

## 开发注意事项

- **必须跑接收队列补丁**，否则一包 1930 字节的打印数据在 512 字节队列里会静默丢包；
- **不要用 `availableForWrite()`**：这版 `BluetoothSerial` 没实现，基类永远返回 0，会死循环；发送用 `write()` 返回值 + `hasClient()` 重试；
- **LAT 极性是 idle 低 / 脉冲高**，教程写的低有效是错的（LAT 同时门控加热通路，按教程接不出黑）；
- **段间冷却 300µs 是隐形参数**：太短会出现"打几毫米后变白"，排查时优先把它加回 500µs；
- **打印循环里必须保留 `delay(2)`** 喂 task WDT（5 秒超时），否则整页打印中途复位；
- Flash 已用 82.2%，加 GB2312 字库（约 211KB）需换 `huge_app.csv` 分区（代价是放弃 OTA）。

## 已知限制

- **速度**：约 3.7 mm/s，打 100mm 小票约 27 秒。发热能量、升压回充、电池掉压是三条硬约束；
- **iPhone 不可用**：经典蓝牙 SPP 在 iOS 上不开放；
- **无内置字库/条码**：只能打印上位机排好的点阵，脱离 App 无法打文本；
- **无设备主动上报**：协议没有事件帧，上位机只能轮询 `GET_STATUS`；
- **NTC 断线不触发保护**：断线时测温返回 −99，而分级逻辑把负值判为正常，是已知缺陷；
- **无 OTA、无长稳测试数据**：未做过断连重连与批量一致性验证。

## 路线图

- [x] **M1 可靠性补齐**：低电分级、温度补偿、状态灯、自动待机、链路排空、SPI 引脚冲突、溢出保护
- [ ] **M2** 内置字库 + 中文文本 / 条码 / 二维码
- [ ] **M3** 自有指令集（脱离喵喵机协议，做通用打印机）
- [ ] **M4** BLE（支持 iOS / 小程序）或 WiFi 云打印 + OTA
- [ ] **M5** 断连重连、长时间稳定性、批量一致性验证

> 关于"双任务改造"：评估后改为"排空 + 忙标志"。打印循环里 `delayMicroseconds` 是忙等，
> 任务化并不能让主循环真正空闲，而残留错帧（真正的风险）已由链路排空解决。
> 若以后要支持"边收边打"或多页队列，仍需引入双任务 + 环形缓冲。
